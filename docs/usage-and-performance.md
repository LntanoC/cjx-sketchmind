## 怎样触发

最明确的指令是在消息中写出技能名称：

```text
$cjx-sketchmind 用一张中文彩色手绘图解释 Java CAS，展示预期值、当前值、新值和失败重试。输出可编辑 Excalidraw 和预览，附三条关键解释。
```

也可以写“使用 cjx-sketchmind 技能……”。自然语言匹配由技能的 `description` 引导，例如：

- 用手绘白板图讲解 Redis 缓存穿透原理。
- 画出订单服务、库存服务和 Kafka 之间的消息时序图。
- 用状态图解释线程从等待到被唤醒的过程。
- 根据当前项目代码画架构图，并解释模块职责。

自然语言匹配不是固定关键词开关，也不保证每次选中；明确指定技能最可靠。“生成一张图片”缺少技术图解语境，可能选择其他绘图能力；“CAS 是什么”这样的简单定义，技能本身允许先给短文字，不强制画图。

当前安装目录没有 `agents/openai.yaml`，未设置显式禁止自动调用的技能策略。本轮上下文已列出 `cjx-sketchmind`。仅把技能同步到桌面文件夹，并不代表其他客户端也会自动加载它。

官方依据：[技能触发与描述匹配](https://learn.chatgpt.com/docs/build-skills)。

## 当前快速模式

- 默认一张核心静态图，加简短解释；完整教学和多幕仍按用户要求提供。
- 默认生成 `.excalidraw` 与 PNG，保留原生图元、箭头绑定及预览验证。
- SVG 按需：`--preview both` 导出两种预览，`--preview svg` 只导出矢量预览。
- 已有原生图补导出 SVG 用 `render --preview svg`，无需重新转换 Mermaid。
- 环境正常时直接构建；首次安装或环境错误时才运行完整自检。
- JSON 返回 `timingsMs` 与本次 `outputs`。输出目录里同名但未重新导出的旧文件不属于本轮交付。
- v1.3 的新图默认应用教学配色，复杂图用 `--design` 配置阶段、卡片、强调与修正分支。样式在内存中完成，不新增浏览器启动；普通 `render` 不改动现有图。

```powershell
node "<技能目录>/scripts/excalidraw.mjs" build "01-overview.mmd" --out "01-overview"
node "<技能目录>/scripts/excalidraw.mjs" render "01-overview.excalidraw" --out "01-overview" --preview svg
```

## 旧版为什么会慢

1. **每张图包含三次串行 CLI 操作。** `scripts/excalidraw.mjs` 先运行 `mermaid` 生成场景，再分别 `render` SVG 和 PNG；每次执行都是独立 Node 进程。检查当前 CLI 的 `dist/render-NNQZJBA2.js` 可见转换/渲染流程启动无头浏览器、创建页面，并在结束时关闭浏览器，存在重复启动与页面初始化开销。
2. **默认交付范围较大。** 除 `.mmd` 外还交付 `.excalidraw`、SVG、PNG，并检查 PNG。复杂主题默认拆成 2–5 幕，多图会重复执行链路。
3. **画图前后也需要时间。** 建立正确知识模型、规划节点和连线、按需读取代码或核实技术细节、查看预览、修正布局、撰写讲解，均不包含在上述 11.524 秒中。
4. **重复完整诊断会再绘制一张测试图。** 若普通绘图前每次都运行 `doctor --smoke`，会额外执行整套测试。现有说明只要求首次安装或环境异常时自检，不需要每次都做。
5. **失败与修图会重走部分或全部流程。** 当前脚本每次 build 都导出两种预览；即使只是小修改，也会重新转换和渲染。

中文手写字体由 Excalidraw CLI 按需加载并缓存，首次遇到未缓存的字符时可能下载字体。可通过 `--fonts-url` 指定本地字体目录。链路是 Windows 本地 Node/浏览器，不依赖 WSL。当前也没有证据证明内存不足或网络是此前慢请求的主因。

## 控制任务范围的指令

```text
$cjx-sketchmind 用一张静态中文图解释 Java CAS，只展示预期值、当前值、新值与失败重试，不展开 ABA。输出默认可编辑文件和预览，附三条说明；本次不需要多幕或动画。环境正常时直接构建，遇到环境错误再诊断。
```

这会缩小内容规划与输出范围，仍保留默认渲染和必要的质量检查，不能保证固定完成时间。
