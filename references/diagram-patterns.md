# 图示模式库

从场景的主体、动作和变化出发；以下是可组合的表达工具，不是可绘制类型的完整清单。自由场景、连续快照及主体概描见 [场景构图指南](scenario-composition.md)。

## 1. 概念关系图

适用：CAS 三要素、AQS 结构、JVM 内存区域、倒排索引概念。

结构：
- 中心概念；
- 3–7 个关键组成；
- 用“包含 / 依赖 / 解决 / 导致”等词标注关系；
- 必要时增加一个具体例子。

## 2. 架构图

适用：微服务、日志链路、Agent 系统、缓存架构。

结构：
- 默认以系统的组件、层次、边界和关系为主，而非依照调用步骤串成单链；可根据视角选择分层、部署或其他结构；
- 同层组件并列，跨层依赖沿实际方向连接；按实际部署或信任边界嵌套分区；
- 每个组件标注职责；
- 连接线标注协议或交互动作；
- 区分同步调用、异步消息、数据持久化；
- 关键边界（网络、事务、信任边界）明确标出。
- 具体构图与证据要求见 [架构构图指南](architecture-composition.md)。

## 3. 时序图

适用：HTTP 调用、MQ 消费、分布式事务、登录鉴权。

结构：
- 参与者作为列；
- 时间从上到下；
- 每条消息标注动作；
- 返回消息使用反向箭头；
- 异步消息用虚线或不同线型；
- 异常分支用单独区域表示。

## 4. 数据流图

适用：日志采集、ETL、Kafka、搜索索引构建。

结构：
- 数据源；
- 处理节点；
- 缓冲/队列；
- 存储目标；
- 重试、死信、限流、背压等治理机制。

## 5. 状态机

适用：订单、报销单、锁状态、任务状态。

结构：
- 状态作为节点；
- 事件/条件作为边标签；
- 标出初始状态和终态；
- 明确失败、超时、补偿、重试路径；
- 不允许凭空添加状态迁移。

## 6. 并发时间线

适用：CAS、锁竞争、线程池、消费者并发。

结构：
- 每个线程/参与者一条泳道；
- 时间从上到下；
- 读取、计算、CAS、成功/失败分别标记；
- 使用不同颜色区分线程，但状态颜色仍遵守语义；
- 明确共享变量何时发生变化；
- 对关键竞态增加“此刻内存值”标注。

## 7. 对比图

适用：Redis Sentinel vs Cluster、Saga vs Seata、HashMap vs ConcurrentHashMap。

结构：
- 两列或多列；
- 比较维度保持一致；
- 最下方给出适用场景和选择原则；
- 避免只罗列优缺点，不解释原因。

## 8. 多幕教学图

复杂主题默认拆成 2–5 幕：
1. 全局地图：先知道有哪些角色；
2. 正常路径：按时间走一遍；
3. 关键机制：放大解释最难的部分；
4. 异常路径：失败、重试、补偿；
5. 总结图：把知识点串起来。

每一幕应解决一个明确问题。不要重复绘制同一张大图，只高亮当前讲解区域即可。
