# 图示质量检查清单

生成后逐项检查。发现问题时优先局部修复。

## 技术正确性
- [ ] 若是系统架构图，组件、层级、边界、连接方向与证据一致；并列组件没有被画成顺序步骤，未知关系未被编造。
- [ ] 若采用图标和典型场景，关键组件图标与名称对应，架构连线语义可辨；场景能追踪触发方、输入、交接与结果，场景假设有标注。
- [ ] 组件名称和职责准确。
- [ ] 箭头方向符合真实调用/数据方向。
- [ ] 时间顺序正确。
- [ ] 同步与异步没有混淆。
- [ ] 读写方向、生产消费方向准确。
- [ ] 状态迁移有明确触发条件。
- [ ] 失败、重试、超时、补偿路径没有被误画。
- [ ] 没有把示例假设说成系统事实。

## 可读性
- [ ] 一张图只有一个核心主题。
- [ ] 标题能表达要解决的问题。
- [ ] 中文标签清楚，没有过长段落。
- [ ] 连线不穿过节点文字。
- [ ] 交叉线尽可能少。
- [ ] 颜色数量适中且语义一致。
- [ ] 有足够留白。

## 教学性
- [ ] 画面按主体、动作和状态变化组织，阅读顺序清楚；图形类型服务于问题。
- [ ] 主体概描有明确对应标签，同类主体一致，比喻没有引入虚假行为或顺序。
- [ ] 先有全局概览，再有局部机制。
- [ ] 读者知道从哪里开始看。
- [ ] 关键箭头标注动作。
- [ ] 关键状态变化有解释。
- [ ] 至少指出一个常见误解（适用时）。
- [ ] 能够根据图复述核心原理。

## 文件与动画
- [ ] 源文件实际存在且可打开。
- [ ] 原生 `.excalidraw` 含可编辑节点、文字与有效绑定，不是单张图片或改后缀的 SVG。
- [ ] 所选预览均从交付的同一原生场景渲染，并实际打开预览检查中文与排版；默认只需要 PNG，SVG 按需。
- [ ] 修改已有图时保留用户手工编辑，不用过期 Mermaid 覆盖。
- [ ] 如果交付 SVG，确认有 `viewBox`，缩放时不失真。
- [ ] HTML 不依赖不必要的外部 CDN。
- [ ] 动画有暂停/逐步控制，或提供静态回退。
- [ ] 动画不会遮挡标签。
- [ ] 没有不必要的大型 base64 图片。
- [ ] 只报告本次 `outputs` 中实际验证过的输出格式，不把旧预览当作新结果。

## 视觉设计（按图的复杂度适用）
- [ ] 默认彩色手绘白板效果可见，组件颜色与线条含义一致；有多个连线语义时配图例，图标和装饰不影响阅读。
- [ ] 角色配色稳定；阶段背景不被误读为新的系统组件。
- [ ] 有阅读顺序，关键步骤编号不挤占箭头标签。
- [ ] 箭头写短动作，卡片展示输入/输出，内容不重复堆叠。
- [ ] 标题、阶段、角色和补充文字有字号层级。
- [ ] 实线、返回虚线和局部修正具有可解释的图例；说明卡片默认按编号对应，不增加关联箭头。
- [ ] 组件、文档卡片、判断菱形符合语义。
- [ ] 仅强调 1–2 个核心机制，其他内容保持安静。
- [ ] 卡片不相互覆盖，连线不穿过无关文字，返回线不造成大块空白。
- [ ] 有判断时展示通过与修正路径，回流留在独立区域，不穿过主时序；没有业务重试就不凭空编造业务重试。
- [ ] 原生样式已实际渲染；美化已有图时原图未被覆盖，ID/绑定和方向保留。
