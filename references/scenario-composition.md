# 场景构图指南

## 先设计发生了什么

1. 明确一个读者的问题和核心变化，辨认真实主体、动作、前后状态和关键约束。
2. 选读图顺序：单幅空间关系、按时间排列的快照，或必要时拆成多幅；把发生变化的对象放在视觉焦点，重复主体保持位置和样式稳定。
3. 只有能帮助识别或解释时才给主体加简笔概描。标明真实名称，动作使用短标签；用编号或时间标明快照，不用装饰性箭头暗示因果。
4. 局部需要精确表达时组合时序、状态、流程等专业符号；用户要求标准记法时遵从标准。场景复杂时删去无关细节，不删影响结论的边界条件。

## 例子：线程池的任务去向

问题是“任务多起来时发生什么”，可以画连续快照：工作线程处理任务卡片、后来的任务在队列等待、入队失败后尝试增建线程、资源耗尽触发拒绝。写明这些是示例瞬间及参数假设，不把图中的排队顺序误画为完成顺序；池已关闭也可拒绝任务。若问题是 execute 的判断次序，决策流程图可能更清楚。两种画法可以组合，但不必每次都画两张。

## 可编辑实现

- 简单场景先用 Mermaid 节点、分区、卡片和短标签表达，参考 `templates/scenario-thread-pool.mmd`，再用本地 `build` 生成原生 Excalidraw 和 PNG。模板是示例，不是唯一布局或自动插画生成器。
- Mermaid 无法清楚表现主体时，可在生成的原生场景中添加少量 Excalidraw 可编辑基础形状、线条和文字，或使用可用的原生场景编辑工具；保留原有图元、绑定及技术标签。再用 `render` 从修改后的场景生成预览。编辑前保留源 Mermaid；手工改动后以 Excalidraw 为权威源，不用旧 Mermaid 覆盖。
- 没有可靠的原生编辑能力时，使用清晰的带标签节点替代，并如实说明；不要声称已经生成了主体插画。避免把整个图嵌为单张图片而冒充可编辑图。
- 打开最终预览，检查主体辨识、中文、阅读顺序、连线和真实机制；若构图与机制冲突，以正确性为先。
